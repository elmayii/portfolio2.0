## Request

`POST https://api.srperera.com/lead`, `Content-Type: application/json`

```json
{ "email": "ana@example.com", "keyword": "playbook", "source": "instagram", "consent": true }
```

| Field | Rule (as implemented) |
|---|---|
| `email` | string, required; trimmed + lowercased; must look like `x@y.z`, ≤ 254 chars → else `invalid_email` (non-string/missing → `invalid_body`) |
| `keyword` | optional; trimmed + lowercased; `[a-z0-9-]{1,64}`; absent/blank → sign-up without guide (no email) |
| `source` | `instagram` · `tiktok` · `web` |
| `consent` | must be JSON `true` |
| `turnstile` | optional string ≤ 2048; required when no valid `X-Lead-Secret` |

Auth, one of: header `X-Lead-Secret` equal to `LEAD_SECRET` (constant-time compare), or a
`turnstile` token that siteverify accepts with a hostname in `TURNSTILE_HOSTNAMES`. The per-IP
limit applies only to the Turnstile path. A wrong secret falls back to Turnstile.

Order: JSON parse → validation (400) → auth (403 / 429) → D1 → email. Validation goes first so a
malformed request never burns a single-use Turnstile token.

## Responses

| Code | Body | When |
|---|---|---|
| 200 | `{"ok":true,"sent":true}` | stored and the guide email was sent |
| 200 | `{"ok":true,"sent":false}` | stored; no keyword, or the email + keyword already had 3 requests today (UTC), or the send failed (logged as `send_failed <code>`, never the address) |
| 400 | `{"ok":false,"error":"invalid_email"}` / `{"ok":false,"error":"invalid_body"}` | malformed data (incl. non-JSON body, `consent` ≠ `true`, unknown `source`, bad keyword) |
| 403 | `{"ok":false,"error":"forbidden"}` | no valid secret and no valid Turnstile token |
| 429 | `{"ok":false,"error":"rate_limited"}` | web path over 5 requests / 60 s from the same IP |
| 404 / 405 | empty | any other path / any method but POST (outside the contract) |
